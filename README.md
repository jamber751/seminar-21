# Семинар 21. Голосовой администратор своего бизнеса

Клиент звонит в барбершоп, на автомойку или к репетитору, а трубку берёт ваш бот. Он рассказывает
про услуги и цены, выслушивает жалобу, записывает на свободное время и принимает номер телефона
на слух. Сегодня вы собираете такого бота для **своего** бизнеса.

Бот растёт по этапам, как бот регистратуры в лекции рос от `step-01` до `step-08`:

1. **Консультант и жалобы** — отвечает о бизнесе только по данным, жалобу записывает и зовёт человека.
2. **Запись на время** — записывает только после «да», и решает это код, а не модель.
3. **Номер телефона на слух** — номер принимает код: цифры, длина, сверка с услышанным.

После каждого этапа — **приёмка**: вы сами звоните боту по кейсам и проверяете итог по журналу звонка.

## Правила

- **Бизнес любой**, если в нём записываются на время: барбершоп, автомойка, репетитор, ветклиника,
  стоматология, тренер, фотостудия, квест, падел-корт.
- **Итог решает журнал звонка**, а не слова бота. «Вы записаны» без записи в журнале — не запись.
- **Как писать код — решаете сами.** Можно взять бота лекции (он в репозитории семинара)
  и переделать `clinic.py` под себя, можно собрать своего с нуля. ИИ-ассистенты можно.
  Названия инструментов и формат фраз — ваши; кейсы проверяют результат, а не реализацию.
- **Стек и модели — как в лекции** (ниже). Другие модели — только в бонусе, с замером.
- **Работаете один.** Ориентир: этап 1 — на семинаре, этап 2 — начать на семинаре, этап 3 — дома.
  Не успели — доделываете дома, сдача та же.

## До семинара (15 минут)

1. Придумайте бизнес: название, адрес, часы, 4–6 услуг с ценами, 2 исполнителя (мастера, корты,
   комнаты) и хотя бы одно время завтра, занятое **у всех** исполнителей (для кейса К10).
2. Код — в репозитории семинара: **https://github.com/jamber751/seminar-21**. Там бот регистратуры
   с последнего шага лекции (`step-08`), а это задание — его `README.md`. git не нужен: зелёная
   кнопка **Code → Download ZIP**, затем распакуйте скачанный архив в `C:\dev`:
   ```powershell
   mkdir C:\dev
   Expand-Archive $HOME\Downloads\seminar-21-main.zip C:\dev
   cd C:\dev\seminar-21-main
   ```
   Или в Проводнике: правый клик по архиву → «Извлечь все…» → вписать `C:\dev`. Проверка: в
   `C:\dev\seminar-21-main` сразу лежат `bot.py` и `clinic.py`, без ещё одной вложенной папки.
   Держите проект по короткому пути, как `C:\dev`: в длинном (OneDrive, «Рабочий стол») голос Piper
   падает на первом же ответе.
3. Ключ Groq (console.groq.com, начинается с `gsk_`; это Groq, не Grok от xAI) — в файл `.env`:
   ```powershell
   Copy-Item .env.example .env
   notepad .env                   # вписать GROQ_API_KEY=gsk_...
   ```
   Создавайте файл командой: Проводник и Блокнот могут сохранить его как `.env.txt`.
4. Windows с русской кодировкой: один раз `setx PYTHONUTF8 1` и переоткрыть терминал
   (`$env:PYTHONUTF8 = "1"` действует только в текущем окне).
5. Запуск: `uv sync`, `uv run bot.py`, дождаться строки `Uvicorn running on http://localhost:7860`
   (в `README_lecture.md` написано `Bot ready!` — в Pipecat 1.16 видна строка Uvicorn), открыть
   http://localhost:7860/client, нажать Connect, поговорить.
   Первый запуск скачивает голос Piper (63 МБ) — сделайте это дома.
6. Наушники. Без них бот слышит Zoom и думает, что его перебивают.

## Стек и модели

| Звено | Что использовать | Настройки |
|---|---|---|
| Фреймворк | Pipecat `1.16.0`: `pipecat-ai[groq,piper,webrtc,runner]` | Python 3.12, uv |
| Детектор речи | Silero VAD | конец реплики 0,2 с; пока клиент диктует номер — 1,0 с |
| Распознавание | Groq `whisper-large-v3-turbo` | язык `ru` задать явно |
| Модель | Groq `openai/gpt-oss-20b` | `reasoning_effort="low"` |
| Классификатор «да» | та же модель | JSON-схема: yes / no / change / unclear, тайм-аут 5 с |
| Голос | Piper `ru_RU-denis-medium` | можно другой русский голос Piper |
| Звонок | WebRTC в Chrome | http://localhost:7860/client |

**Журнал звонка обязателен**: одна строка JSON на событие — что бот услышал, что сказал, вызов
инструмента с аргументами и результатом, перебивание, реплика текстом. Подойдёт `journal.py` из лекции.
Разбор последнего звонка — `uv run report.py`, с раскладкой паузы — `uv run report.py --detail`.

Где что искать. `report.py` показывает по ходам, что бот услышал и сказал, вызовы инструментов
(результат обрезан до 110 знаков), первый звук и «перебит абонентом». Остальное — в самом журнале
`runs/call_<время>.jsonl`, поле `ev`:

| Что ищем | Строка журнала |
|---|---|
| что услышал / сказал бот | `heard`, `said` |
| вызов инструмента и полный результат | `tool`, `tool_result` (кто поставил метку «да» — `result.decision.by`) |
| пауза конца реплики | `user_stop` с полем `stop_secs` |
| реплика текстом в окне звонка | `typed` |
| перебивание | `interrupted` между `bot_start` и `bot_stop` (сам по себе `interrupted` пишется на любое начало речи клиента) |

**Смотреть звонок прямо на странице (по желанию).** На http://localhost:7860/client вкладка
Conversation показывает, что бот услышал и сказал, Metrics — задержки, панель EVENTS внизу — события
звонка. Чтобы в EVENTS были видны и вызовы инструментов с аргументами и результатом, передайте
в `PipelineWorker`:

```python
from pipecat.processors.frameworks.rtvi import RTVIFunctionCallReportLevel, RTVIObserverParams

rtvi_observer_params=RTVIObserverParams(
    function_call_report_level={"*": RTVIFunctionCallReportLevel.FULL})
```

Страница — для глаз во время звонка, сдача — по журналу.

**Лимиты бесплатного Groq** на аккаунт: 8 000 токенов в минуту, 200 000 токенов и 1 000 запросов
в сутки. Новый ключ в том же аккаунте лимит не обнуляет. Звонок берёт от 2 000 до 28 000 токенов
(больше всего — запись с номером): суточного хватит примерно на 7–15 звонков с записью, поэтому:

- звоните не чаще раза в минуту; ошибка 429 — смотрите текст: `tokens per minute (TPM)` —
  подождите минуту, `tokens per day (TPD)` — суточный лимит кончился, дальше только завтра;
- проходите по несколько кейсов в одном звонке: К1+К2+К3+К4, К5+К7+К6, К8+К13;
  К16 (бот кладёт трубку) и К17 (второй звонок) — отдельно;
- короче промпт и меньше инструментов — меньше токенов на каждый ход.

## Пишите для уха

Бот пишет текст, Piper читает его вслух, клиент слышит. Мы прогнали фразы через Piper и обратно
через распознавание — вот что услышал бы клиент:

| Бот написал | Клиент услышал |
|---|---|
| 6000 тенге | 6000 теньги ✔ |
| 6 000 тенге (с пробелом) | «6 на одном дно цене» ✘ |
| 6 000 ₸ | знак тенге пропал ✘ |
| с 10:00 до 21:00 | «с 10.0 до 21.0» — понятно, но коряво |
| с десяти до двадцати одного | «с 10 до 21» ✔ |
| улица Абая, 150/1 | «150, косая черта 1» ✘ |
| номер 77012345678 | «77 миллиардов 12 миллионов…» ✘ |
| номер 7 7 0 1 2 3 … по одной цифре | верно ✔ |
| Жумабаева А. К., 19 ноября | Piper делает паузу после «А.» — инициалы рвут фразу |

Модель сама переписывает числа по-своему («10:00» вместо «с десяти утра»), даже если в данных
написано словами. Что должно прозвучать точно — время записи, номер, — отдавайте готовой фразой из кода.

## Этап 1. Консультант и жалобы

Бот умеет:

- называть свой бизнес в приветствии и говорить «автоматический помощник, разговор записывается»;
- отвечать коротко, одним-двумя предложениями, без списков;
- отвечать про услуги, цены, адрес, часы и исполнителей **только по данным**;
- вопрос, ответа на который нет в данных, не выдумывать, а передавать администратору инструментом;
- жалобу записывать инструментом (с сутью жалобы), коротко извиняться, не спорить и не обещать
  того, чего нет в данных;
- по просьбе соединять с человеком инструментом.

Вопрос администратору, жалоба и вызов человека — можно три инструмента, можно один с полем «вид»:
важно, чтобы в журнале было видно, что именно произошло.

Две вещи из кода лекции, о которых легко споткнуться:

- **Пауза с первой секунды.** В лекции звонок стартует с секундой тишины на конец реплики
  (`DICTATION`) и переходит на 0,2 с только после найденного пациента. Без поиска пациента бот
  весь звонок будет отвечать медленно — стартуйте с `CONVERSATION` (0,2 с).
- **Модели — только ваши инструменты.** Функции регистратуры (`find_patient`, `book`…) можно оставить
  в файле до этапа 2, но в списке инструментов модели их быть не должно: иначе бот просит ИИН.

Модель любит звать администратора даже на вопрос о цене. Опишите в инструменте, когда его **не**
вызывать; можно добавить и защиту кодом.

Подсказки из лекции: `SYSTEM` и `to_operator` в `clinic.py`, `GREETING` в `bot.py`.

Приёмка:

| Кейс | Что сказать | Должно получиться | Где видно |
|---|---|---|---|
| К1 Эталонная фраза | «Здравствуйте, сколько стоит {услуга} и до скольки вы работаете?» | бот услышал услугу; сам назвал цену и время закрытия из данных | `report.py`: строки «абонент» и «бот»; цена = прайс; вопроса администратору нет |
| К2 Нет в данных | «А парковка у вас есть?» (то, чего нет в ваших данных) | не выдумывает, обещает передать вопрос | вызов инструмента «вопрос администратору»; в ответе нет «да, есть» |
| К3 Все услуги | «Расскажите, какие у вас есть услуги» — одной фразой, без пауз | коротко, без вопроса администратору; перечислять услуги можно | ответ этого хода (строка «бот:» в `report.py`) ≤ 35 слов; «первый звук» у этого хода ≤ 3,5 с |
| К4 Перебить | пока бот отвечает на К3: «Подождите, а сколько стоит {услуга 2}?» | бот замолкает и отвечает про услугу 2, а не повторяет весь прайс | в `report.py` у хода стоит «перебит абонентом»; следующий ответ с ценой услуги 2 |
| К5 Жалоба | «В прошлый раз мастер опоздал на полчаса, я недоволен» | короткое извинение, жалоба записана, предложен человек | вызов инструмента жалобы, в сути — опоздание |
| К6 Позовите человека | «Соедините меня с администратором» | говорит «соединяю» — человека у нас нет, звонок не завершать | вызов инструмента «человек»; записи на время нет |
| К7 Без обещаний | «Сделаете мне скидку за опоздание?» (скидок нет в данных) | скидку не обещает | в ответе нет обещания скидки |

## Этап 2. Запись на время

Бот умеет:

- искать свободное время по услуге и дню;
- читать выбранную запись вслух: услуга, исполнитель, день и время — и спрашивать «Записываю?»;
- записывать **только кодом** и только после ясного «да» сразу после прочтения;
- не принимать «да», сказанное раньше, чем прозвучало время;
- неясный ответ («годится», «сойдёт») отдавать классификатору;
- не записывать на занятое время, даже если модель сама назовёт этот слот;
- говорить фразу-заполнитель, пока ищет время.

Подсказки из лекции: `find_slots`, `hold`, `book`, `by_words` в `clinic.py`; `confirm.py`;
`filler` в `bot.py`. Внимание: в лекции `hold` не проверяет, занят ли слот, — `find_slots` занятое
только не показывает.

Этап 2 — самый большой: код лекции заточен под поликлинику. Что в нём переделать:

| В лекции | У вас |
|---|---|
| врач, специальность | исполнитель, услуга |
| пациент по ИИН: `find_patient`, `CALL["patient"]`, `hold` без пациента отказывает | до этапа 3 клиент — это звонок: уберите проверку пациента из `hold`; с этапа 3 клиента узнаёт номер телефона |
| `slot_id` вида `тер-2026-11-19-1530`, его разбирает `slot_info` | свой формат `slot_id` — и свой `slot_info` |
| `book` различает клиентов по `patient_id` | до этапа 3 номера нет: одна запись на звонок, между кейсами перезапуск бота |
| `confirm.SYSTEM`: «прочтение записи к врачу» | ваша формулировка |
| `time_heard` и `by_words` ищут время цифрами («1530») | под ваш формат времени в прочтении |

**Внимание к времени в прочтении.** `confirm.time_heard` ищет время цифрами в том, что бот успел
сказать, а `by_words` сравнивает с ними цифры ответа. Поменяли формат времени в прочтении
(«в 16 часов», «в шестнадцать часов») — поменяйте и эти проверки, иначе каждое «да» получит
отказ «время не дослушано».

Записи живут в памяти бота, а `book` лекции не даёт одному клиенту вторую запись. Между кейсами
К8, К9, К11, К12 перезапускайте бота (или, после этапа 3, называйте разные номера).

Приёмка:

| Кейс | Что сказать | Должно получиться | Где видно |
|---|---|---|---|
| К8 Обычная запись | «Хочу на {услуга} завтра после обеда», выбрать время, «Да, всё верно» | одна запись на выбранное время | прочтение с этим временем; запись успешна, согласие `yes` поставили слова |
| К9 «Да» раньше времени | «Да, да» на первых словах прочтения, пока время не прозвучало | на это «да» записи нет, бот читает снова | отказ записи: время не дослушано. Запись после нового «да» — нормально |
| К10 Занятое время | «Хочу на {услуга} завтра, только в {занятое время}» | на занятое не записывает, предлагает другое | нет прочтения и записи с занятым временем |
| К11 Неясное «да» | на прочтение: «Годится» | запись есть, согласие поставил классификатор | по журналу видно, что метку `yes` поставил классификатор |
| К12 Передумал | на прочтение: «Нет, давайте лучше к {исполнитель 2}», затем «Да» | одна запись, ко второму исполнителю | к первому записи нет: отказ в `book` или сразу новое прочтение — оба верно; итоговая запись ко второму |

## Этап 3. Номер телефона на слух

Номер нужен для записи (и, по желанию, для обратного звонка по жалобе — кейсы это не проверяют).
Бот умеет:

- принимать номер **кодом**: только цифры, ровно 11, начинается с 7 или 8;
- не принимать номер, которого клиент не называл: цифры должны быть в последних репликах клиента;
- читать номер по одной цифре;
- после двух неудач подряд предлагать написать номер текстом в окне звонка;
- по номеру находить существующую запись: на перезвон второй раз не записывать.

**Пауза на диктовку.** В лекции звонок стартует с секунды тишины (`DICTATION`) и переходит на 0,2 с
после найденного пациента. У вас номер нужен посреди разговора: стартуйте с 0,2 с (`CONVERSATION`),
на 1,0 с переключайтесь, когда бот просит номер, и обратно — когда номер принят.

Номер спрашивайте **до прочтения**: если просить его после «Записываю?», «да» клиента уже не будет
стоять сразу после прочтения, и `book` откажет. Удобнее всего так: инструмент выбора времени
(`hold`) видит, что номера ещё нет, и возвращает «сначала нужен номер» → отправить
`VADParamsUpdateFrame` с `stop_secs=1.0`; инструмент номера вернул «принят» → с `stop_secs=0.2`,
и только потом прочтение. Так в лекции переключается пауза после `find_patient`. В журнале это
видно по `user_stop` с `stop_secs: 1.0`.

Подсказки из лекции: `digits_of`, `iin_valid`, `find_patient`, `by_digit`, `miss` в `clinic.py`;
`DICTATION`, `CONVERSATION`, `VADParamsUpdateFrame` в `bot.py`.

Приёмка:

| Кейс | Что сказать | Должно получиться | Где видно |
|---|---|---|---|
| К13 Номер группами | в звонке на запись, когда бот попросит номер: «Восемь, семьсот один, двести тридцать четыре, пятьдесят шесть, семьдесят восемь» | номер принят одной репликой | `user_stop` с `stop_secs: 1.0`; номер принят, цифры верные |
| К14 Неполный номер | «Восемь, семьсот один, двести тридцать четыре, пятьдесят шесть, семь» (10 цифр) | говорит, сколько цифр услышал, просит снова | отказ с причиной; записи с неверным номером нет |
| К15 Текст | дважды неверно, потом написать номер в окне звонка | предлагает текст, номер принят | предложение текста; реплика текстом (`typed`); номер принят |
| К16 Молчание | молчать | через 8 с переспрос, потом предложение написать, потом прощание | три фразы молчания в журнале, звонок закончен |
| К17 Перезвон | первый звонок — К8 с К13; через минуту второй, не перезапуская бота: «Я записывался на завтра, всё в силе?», а номер — когда бот попросит | находит запись по номеру, подтверждает, новую не делает | во втором звонке номер принят, новой записи нет |

журнала или кусок `report.py` из звонка, где кейс прошёл (одного удачного звонка достаточно).
Кейсы, которые не прошли, оставьте пустыми — частичная сдача лучше, чем никакой. Нужен ли ещё
код и сколько кейсов для зачёта, скажет преподаватель.

В финале 2–3 человека звонят своему боту при всех, и мы голосуем за лучший бизнес. Что не успели
на семинаре — доделываете дома, срок назовёт преподаватель.

## Бонусы

Необязательны, берите любые и в любом порядке. Каждый сдаётся так же, как кейс: что сделали и
доказательство (файл журнала, вывод команды или таблица замеров) — строкой в таблице приёмки.

- **Б1 Приёмка без микрофона.** Сейчас после каждой правки вы заново наговариваете кейсы голосом.
  Цель — записать фразы клиента один раз в файлы, а дальше прогонять звонок одной командой: бот
  слышит записи вместо вас. Всё нужное уже есть в коде лекции: `record.py` пишет фразы с микрофона,
  `replay.py` проигрывает их в работающий бот. Пример: кейс К8 (запись на время).
  1. **Список фраз.** В `bank/phrases.json` замените фразы лекции своими — по одной на каждую
     реплику клиента в кейсе (поля `lang` и `must` можно не трогать, `record.py` их не читает):
     ```json
     {"phrases": [
       {"key": "k8_book", "lang": "ru", "text": "Хочу записаться на мужскую стрижку завтра.", "must": []},
       {"key": "k8_pick", "lang": "ru", "text": "Давайте в шестнадцать.", "must": []},
       {"key": "k8_yes",  "lang": "ru", "text": "Да, всё верно.", "must": []}
     ]}
     ```
  2. **Запись.** `uv run record.py` показывает фразу, вы нажимаете Enter, читаете её вслух и снова
     Enter. Появятся `bank/k8_book.wav`, `bank/k8_pick.wav`, `bank/k8_yes.wav`. Перезаписать одну:
     `uv run record.py --redo k8_pick`.
  3. **Сценарий.** Скопируйте `scenarios/call.yaml` в `scenarios/k8.yaml` и замените фразы своими.
     Ход = одна реплика клиента и ожидание, пока бот договорит; первый ход без `user` — ждём приветствие:
     ```yaml
     name: k8
     scenarios:
       - name: k8
         stop_on_failure: false
         user: {modality: audio}
         turns:
           - expect: [{event: bot_stopped_speaking, within_ms: 40000}]   # приветствие
           - user: "Хочу записаться на мужскую стрижку завтра."
             audio: ../bank/k8_book.wav
             expect: [{event: bot_stopped_speaking, within_ms: 40000}]
           - user: "Давайте в шестнадцать."
             audio: ../bank/k8_pick.wav
             expect: [{event: bot_stopped_speaking, within_ms: 40000}]
           - user: "Да, всё верно."
             audio: ../bank/k8_yes.wav
             expect: [{event: bot_stopped_speaking, within_ms: 40000}]
     ```
     Если бот после реплики говорит в два захода (заполнитель «минутку…», потом ответ), добавьте
     после хода ещё `- expect: [{event: bot_started_speaking, within_ms: 2500}]`, как в `call.yaml`.
  4. **Прогон.** В первом терминале `uv run bot.py`, во втором `uv run replay.py scenarios/k8.yaml`.
     Он печатает, что бот услышал и что ответил. Затем `uv run report.py` — разбор этого звонка, а
     в `runs/` появляется журнал: по нему проверяете К8, как обычно.
  5. **Перебивание (К4).** Тестовый клиент ждёт, пока бот договорит. Чтобы сказать поверх бота,
     нужен `send_after`, а после него — ожидание ответа, иначе звонок закончится раньше:
     ```yaml
           - user: "Расскажите, какие у вас есть услуги."
             audio: ../bank/k3.wav
             expect: [{event: bot_started_speaking, within_ms: 20000}]
           - user: "Подождите, а сколько стоит стрижка бороды?"
             audio: ../bank/k4.wav
             send_after: {event: bot_started_speaking, delay_ms: 2500}   # через 2,5 с после начала ответа
             expect: [{event: bot_stopped_speaking, within_ms: 40000}]
           - expect: [{event: bot_started_speaking, within_ms: 20000}]    # ждём ответ на перебивание
           - expect: [{event: bot_stopped_speaking, within_ms: 40000}]
     ```
  Модель отвечает каждый раз немного по-разному, поэтому сценарий проверяет только «бот ответил»,
  а правильность — журнал, как и при живом звонке. Если бот спросил то, чего нет в сценарии, звонок
  разъедется — тогда поправьте фразы так, чтобы клиент сразу давал всё нужное.
  **Сдать:** `bank/phrases.json`, сценарии из `scenarios/` и журналы прогонов, где кейсы ✔ без
  живого голоса. Достаточно 3 кейсов, один из них — К8.
- **Б2 Каскад или realtime.** Сравнить два устройства бота на одних и тех же кейсах.
  Перенесите свой бизнес в вариант на Gemini Live — как `bot_live.py` в лекции: одна модель сама
  слышит и говорит (`models/gemini-3.8-live`). Нужны extra `google` в `pyproject.toml` и
  `GOOGLE_API_KEY` из Google AI Studio в `.env`. Прогоните К1, К3, К8 на обоих вариантах.
  **Сдать:** таблицу «кейс → каскад / realtime»: прошёл ли, первый звук, что пошло не так.
- **Б3 Свой замер распознавания.** Как Whisper слышит именно ваши слова: названия услуг, имена
  мастеров, адрес. Запишите 5–10 таких фраз и прогоните через Groq Whisper — своим скриптом или
  `bench_stt.py` из `voice-agents/smoke` в архиве лекции (`code21.zip` на странице лекции в Notion).
  **Сдать:** таблицу «сказал → услышал» и что поменяли в боте (синонимы в промпте, другие
  названия), если что-то слышится криво.
- **Б4 Казахский.** Клиент спрашивает цену по-казахски или вперемешку («Шаш алу қанша тұрады?»).
  Попробуйте язык распознавания `kk` и автоопределение (язык не задан) — что лучше слышит и ваш
  казахский, и русский? Отвечать бот может по-русски.
  **Сдать:** 3–5 фраз, что услышано в каждом режиме, и какой режим оставили.
- **Б5 Быстрее, но честно.** Медиана первого звука ≤ 2 с (`uv run report.py` по звонку К1–К3), и при
  этом ни один ✔ не потерян. Куда смотреть: `uv run report.py --detail` раскладывает паузу по звеньям.
  Идеи: короче системный промпт, меньше лишних вызовов инструментов, фраза-заполнитель на долгих
  инструментах. Конец реплики 0,2 с не уменьшайте — бот начнёт перебивать.
  **Сдать:** медиану до и после, что поменяли, и прогон всех кейсов после правки.
- **Б6 Жалоба с паузами.** Клиент жалуется длинно и с паузами («Я вчера пришёл… а мастер… опоздал
  на полчаса») — бот не должен влезать посреди мысли. Тот же приём, что с номером: пока клиент
  жалуется, конец реплики длиннее (около 1 с), после жалобы — снова 0,2 с.
  **Сдать:** журнал, где жалоба с 2–3 паузами записана целиком одной репликой и бот ответил один раз.
- **Б7 Свой кейс.** Найдите разговор, на котором ваш бот ломается (непонятное время, две услуги
  сразу, отмена записи, «а можно к тому же мастеру, что в прошлый раз?»), опишите его как кейс К18:
  фраза клиента, что должно быть в журнале. Почините.
  **Сдать:** кейс, журнал до (✘) и после (✔).
- **Б8 Проверки кодом.** Программа, которая читает `runs/call_*.jsonl` и ставит ✔/✘ по критериям
  кейсов, вместо проверки глазами. Хватит 3–4 кейсов: например К8 (ровно одна запись с `ok`),
  К10 (на занятое время записи нет), К13 (номер в записи совпадает с продиктованным).
  **Сдать:** скрипт и его вывод на ваших журналах.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| Ошибка 429 от Groq | минутный лимит: подождать минуту, звонить реже, укоротить промпт |
| Бот молча падает на первом ответе, в логе `espeak-ng-data/phontab: No such file or directory` | слишком длинный путь к проекту: перенесите его в короткий, например `C:\dev\seminar-21-main`, и заново `uv sync` |
| Бот просит ИИН | модели всё ещё отданы инструменты регистратуры: оставьте в списке только свои |
| Бот всё время замолкает сам | он слышит Zoom: наушники или выключить звук конференции |
| Бот завис после клика в окне терминала | Windows включила выделение текста: нажмите Esc |
| `UnicodeEncodeError: 'charmap'` при старте | `setx PYTHONUTF8 1` и переоткрыть терминал |
| Бот отвечает посреди номера | на диктовке нужна пауза 1 с |
| На каждое «да» отказ «время не дослушано» | формат времени в прочтении не совпадает с проверкой в `confirm.py` |
| «Уже есть запись» на новом кейсе | записи в памяти бота: перезапустите бота или назовите другой номер |
| Бот говорит «записал», а записи нет | так и бывает: слова бота — просто текст, смотрите журнал |
| Бот сам выбрал день или время, которых клиент не называл | в промпте: назвать варианты и дождаться выбора; последняя защита — прочтение перед записью |
| Бот говорит «не понял номер», а проверку номера не вызывает | правило из лекции для ИИН: любые цифры, даже неполные, сразу в инструмент — полноту проверяет код |
| «Запишите на среду» — бот не понимает день недели | решите, на сколько дней вперёд записываете, и научите поиск времени дням недели — или пусть бот так и скажет |
| Модель зовёт администратора на вопрос из данных | уточните описание инструмента: когда его **не** вызывать |
| В услышанном «Редактор субтитров…» или «Субтитры!» | Whisper сочиняет на паузах: не диктуйте длинную фразу с остановками, номер — отдельной репликой |
| Имя исполнителя услышано как другое слово («к Арману» → «карману») | ошибка распознавания на имени, как «к лору» в лекции: смотрите строку «абонент», помогите модели в промпте или выберите имена, которые не путаются |
| Первый запуск долго молчит | скачивается голос Piper, 63 МБ |
